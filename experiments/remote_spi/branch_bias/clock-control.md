# Clock control for the MISO input transitions

After the first two bias sweeps on 25 November UTC, the released GPIO28 input changed repeatedly with a single pull-down. In the forward A5 held abort the 126 changes fell in just three of ten project-clock sample phases. GPIO20 did not change in that window. Check whether the pattern depends on the running clock and the trace encoder.

Acquire the raw 16-bit PIO input snapshots through DMA without transition compression. Hold SCK and CS fixed after the original A4/A5 abort, set only the GPIO28 pull-down, and compare a continuous 12.5 MHz clock with one parked low for about 8 µs beginning about 9 µs after the observed MISO disable. Sample continuously for 51.2 µs. Compare the same sample windows in both profiles and reverse the case order in a second block. Require an active correct reply bit before abort, released enable throughout the later observation, and no requester edges in the comparison windows. Determine the boundaries from the separately captured clock witness. Count input changes on both pins before, during and after the pause. Continued changes during a verified quiet clock would challenge the clock-related explanation. A reduction leaves open the physical coupling path, input behavior and analog voltage. No change to the archived FPGA image or qualified project inputs is required.
