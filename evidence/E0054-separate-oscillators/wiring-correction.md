# Fixture correction after the first board attempt

The first image connected the receiver clock to UIO2. On board 1, the SDK detected a high UI2 while entering controller mode and left its driver disabled. The first identity selection physically read `63` instead of `67`. The run stopped before program load or UART transmission and restored the previous design. The provider's pin map documents a direct HAT connection between UI2 and UIO2 through Pi GPIO9. It also documents UI1 and UART UIO1 sharing Pi GPIO10. An initial high or a correct decoded byte cannot establish who owns that net. [First terminal](initial-wiring/terminal.log) · [HAT wiring](https://docs.fpgas.online/en/latest/boards/tt-fpga/overview/pin-mapping.html)

For the corrected bench use UIO4 (RP GPIO29, Pi GPIO26) for the clock witness. Keep the UART on UIO1. During loader writes, stage the payload from the dedicated UI bus using unshared UIO7, then strobe the selector. During readback, return the selected byte on the dedicated UO bus. The FPGA leaves the three HAT-shared bidirectional pins in input mode throughout. Before driving UIO1, release the RP2350's linked UI1 output and read back its output-enable bit. During UART execution, carry the logical selector's bit 1 on the unused UI4 address bit. The raw capture samples GPIO26 through GPIO29 together. This revision changes the bench transport and witness pin. The receiver, binary, two oscillators, time limits, frame checks and host deadline from D56 still apply.
