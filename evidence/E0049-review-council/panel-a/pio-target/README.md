# Single-bit target response, abort and immediate reselection

One native 19-word RP2040 PIO program answered a one-bit request, released MISO after a stopped-low-clock abort and answered a different immediately reselected request without host service. A stopped-high abort defeated the same program. These results apply to the one-bit, externally timed property defined here. The 59-word VM test device instead receives eight command bits, distinguishes A4/A5 from 254 other opcodes, emits eight-bit replies and reports timeouts. The full two-command target comparison remains open.

## Measured results

| Experiment | Observed result |
|---|---|
| Initial 25-word full-polling target | All 36 stopped-low aborts released MISO in 100–158 ns. Each following opposite bit was correct. Normal final-fall release took up to 319 ns. Every one of 60 candidate scenarios failed a normal-closure requirement. All 60 intended control rejections were observed. |
| Revised 19-word program | All 60 in-scope scenarios passed at 0.5, 1 and 2 MHz, including 36 stopped-low aborts, 12 ordinary and 12 selected 2 µs clock-pause scenarios. The first normal release took 101–119 ns. After low-stall abort and reselect it took 100–118 ns. The initial low-stall abort bracket was 100–158 ns. |
| Seeded controls in the revised matrix | Ignoring active CS missed all 36 abort tests. An early-release mutation failed all 12 selected pauses. A constant-one return failed all 12 opposite-bit cases. |
| Stronger stopped-high abort | Both tested phases failed the 160 ns criterion, releasing at 700 and 718 ns. SCK was held high for 600 ns after CS rose. The native WAIT-for-low operation remained blocked. |
| Follow-up 1 ns phase sweep | All 480 three-frame sequences passed the registered *low*-stall and final-normal conditions. Cold and post-reselect abort latency each ranged from 100 to **160 ns**. When coincident raw changes took effect immediately before the sampled edge, both maxima were 159 ns. The after-sample convention produced exactly 160 ns in four cases for each position. The measured model margin is zero at that endpoint. |

The 19-word program uses 38 resident instruction bytes in one PIO SM, a shared instruction memory, X, ISR, OSR, input and output mapping, the ordinary input synchronizer, four GPIOs and no FIFO payload. Cold start executed 73 public 32-bit MMIO accesses and one enable, including writing and reading back all 19 instruction words. The requester supplied SCK0, MOSI1 and CS2. MISO3 was the only enabled target output. The passive fixture recorded output value and direction on all sampled system edges, distinguishing a driven zero from high impedance. The program automatically rearms without consuming status, draining a FIFO, updating an internal transaction ID or performing a host action between frames. A full host/status interface would add resources and tests.

The fixture checked released MISO through the selected command prefix and a matching driven response from at least 60 ns before the response edge through 40 ns after it. Across 84 completed responses in the initial corrected positive matrix, the measured minimum stable setup and hold were 111 and 350 ns. Some frames instead tested release during active output and subsequently chose the opposite bit. The requester schedule supplies old/new MOSI and every clock/CS edge independently of the PIO PC, data outputs and issue timing.

The revised program uses repeated CS tests while waiting for the response clock to rise, then a native WAIT for SCK low to release promptly at the normal falling edge. It waits for CS high before accepting the next select. This solves the registered stopped-low case and explains the high-stall counterexample. At 50 MHz, a 160 ns deadline spans eight core periods. A one-nanosecond digital arrival sweep and both equal-time orderings do not establish a compliant pad or metastability margin. A physical claim needs named load/voltage/clock/receiver, actual release threshold, measurement uncertainty and sample phase. [RP2040 release 13, §§3.4.2–3 and 3.5.6, instruction and GPIO timing](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf#page=312)

## What this changes

The partial PIO target answered the stopped-low ownership and reselection test. C's named VM failure instead raised CS 140 ns after the first response-rising SCK and left SCK high. On that shared clock polarity, both evidence sets reject the 160 ns requirement: 1,563 ns for the 59-word VM fixture and 700/718 ns for this one-bit PIO fixture, which returned SCK low after 600 ns. Their different request duties and high-hold durations preclude a relative speed comparison. The evidence favors spending a bounded comparison day on a full target with mandatory rejection, all response bits and active aborts on either clock level. The 19-word image leaves 13 slots in its 32-word block. Those slots are an implementation budget, not evidence that a complete arbitrary-state target fits. Another SM, a physical output switch or response hardware would each require an explicit resource charge and correct state cleanup. A static native SPI TX FIFO alone cannot choose 3C for A4 and A7 for A5 because the first reply bit already differs while the two command streams differ only at their last bit. A command-dependent decoder or service path must meet that causal deadline. [RP2040 native SSP transmit/receive FIFO behavior, §§4.4.2.4–6](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf#page=480)
