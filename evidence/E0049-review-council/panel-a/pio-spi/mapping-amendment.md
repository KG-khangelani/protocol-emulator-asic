# Additional PIO mapping-stage test

At 15:30 UTC, before any SPI tool run, review of RP2040 datasheet §3.5.6.1 showed one output mapping register and one input mapping register in addition to the two input synchronizer stages. It gives four system cycles for a synchronized zero-propagation loopback. Preserve the initial experiment as a decoder-boundary abstraction with output delay 0 and input delay 2. Treat that boundary as an abstraction in the earlier 1-Wire port as well.

Add a second GPIO-boundary test before accepting any SPI timing inference. Retain the synchronizer and model one output edge of latency plus three external-input edges of latency through the documented stages. First run the original exact binary against edge-only data and expect rejection with the GPIO-boundary timing aligned at CS. A command-stage IN at command-S+2 consumes external raw S−2 under these conventions. Then test an adjusted exact candidate with IN at command-S+4. This consumes external raw S but can expose FIFO-valid only at external S+3. The original VM exposes raw-valid at S+2. Require the stronger time-equality comparison to reject this one-clock difference explicitly. An incorrect mapped candidate one clock early must also fail the edge-only corpus.

Try an extra pre-run forced SET PINDIRS for CPOL/CS initialization, and drop that first instruction from the resident program, to match the VM's absolute A=3/2. Place the PIO completion IRQ one instruction after the mapped CS release. Keep cold-host operations, admission assumptions and the added pre-run pin ownership explicit. The original 144-case decoder matrix remains intact. For the mapped follow-on test nine edge-only patterns and three held variants plus the original exact and one-clock-early controls in all modes/orders. No measured board or physical timing follows from either model. At the datasheet's nominal 5 pF and 1.8 V conditions GPIO1 pad-to-synchronizer delay spans 1.89–5.22 ns and GPIO2 flop-to-pad spans 2.33–7.08 ns. A one-core-edge input value without a physical setup/hold aperture remains a digital stress condition.
