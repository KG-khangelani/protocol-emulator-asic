# Four SPI host modes on one resident RP2040 PIO program

One 30-instruction, 60-byte program transferred an eight-bit word in each direction in all four SPI modes and both bit orders. One unchanged state machine ran all eight settings consecutively. The default synchronized configuration returned the bit present on each declared wire sample and raised completion on the specified edge. Its RX FIFO became nonempty one 20 ns clock later than the VM's archived exact-capture program. In a separate configuration that bypassed the MISO synchronizer, a 20- or 23-instruction phase-specific program reproduced the VM's exact RX-available edge under an additional synchronous-input assumption.

The measured boundary is the pinned Wokwi instruction decoder, official assembled instruction bytes, a 50 MHz digital fixture that models the documented mapping registers, and the project's independent wire equations. The unchanged ASIC RTL comparison used Icarus and is retained in the earlier architecture panel records. These measurements qualify neither physical device nor either implementation's complete public programming contract. ## Program and interface comparison

Here S is the physical-wire sample on the integer grid, Q is CS release, and each half-cycle is 25 clocks or 500 ns. A loaded host transaction transfers one byte on MOSI and one on MISO without service after launch. Positive PIO programs leave MOSI0/SCK2/CS3 driven and MISO1 and uninvolved GPIO released after the transaction, as required. The PIO terminal IRQ asserted at Q+1 and remained set until cleared. The late host popped its result after 400 further core clocks, or 8 µs.

These are occupied image bytes. PIO uses side-set, scratch Y, 32-bit shift registers, counters, GPIO polarity inversion, the divider, one full-word TX preload with eight useful data bits, an RX FIFO word and IRQ0. The port used an exclusive PIO block and SM0. One block has 32 shared instruction slots, leaving two free with the complete SPI image. The earlier 1-Wire port occupies 32 slots. Combining the *unchanged* two PIO programs would require 62 slots, a swap or a second block. The ASIC exposes one 128-word image in a 256×32 physical macro. An 85-word 1-Wire image and one 11-word SPI image total 96 unlinked words, which leaves 32 logical words before adding relocation or dispatch. This capacity arithmetic does not establish working co-residence or independent hardware schedules on the VM. No process-matched PIO synthesis, power, CPU firmware size, board area or end-to-end time was compared. ## Input timing and falsification

At CPHA0 the nominal CS assertion, last sample and terminal edges were respectively 3, 378 and 404. At CPHA1 they were 2, 402 and 428. The common resident image selects starting address 0 or 12 during host setup. The synchronized program pre-establishes clock and CS directions after verifying the image, an ownership and settling assumption before the first scored execution edge. The output register and three input stages comprise one output mapping stage, two MISO synchronizer stages and one input mapping stage. If two histories differ only on their final raw S, the synchronized SM sees identical inputs through S+2. S+3 is the first time its result can depend on that difference under this model. This is a causal bound on this observation point. It determines neither minimum substrate area nor the analog setup aperture. [RP2040 §3.5.6.1](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf#page=331) · [Raspberry Pi PIO designer's timing clarification](https://github.com/raspberrypi/pico-feedback/issues/280#issuecomment-1300078860)

The final independently launched matrix contained **464 desired accepts and 72 required rejections**, totaling 536 cases and 223,520 scored public rows. The eight-frame same-SM sequence is separate. Integer-grid edge-only cases returned 69 hexadecimal and walking-one bytes. Held-target delays were 5 ns, 480 ns and a mixed eight-bit vector. The reactive target saw actual CS and SCK, decoded actual MOSI and switched MISO only after its observed launch edges. Across 56 positive reactive trials in the final matrix, its MOSI byte, eight launch times, eight sample times, actual MISO trace, controller return and terminal time matched. Eight wrong-clock trials made the target refuse, with no decoded bits and controller FF. Eight 520 ns response trials decoded MOSI 96 correctly yet returned D3/B4 in place of 69. Eight deliberately wrong phase-entry selections returned 96, with pin and RX-valid timing errors. Earlier/late captures, omitted mapping registers and wrong synchronizer settings were detected separately. The 56 reactive positives include 48 in the two phase-specific configurations and eight in the common resident program. [Case declarations](declaration.md) · [Reactive peer](clock_peer.cjs) · [Stage-by-stage evidence](records/history.json)

The synchronous bypass's first design used PUSH IFFULL after each IN with automatic push disabled. All 104 extension trials stalled in Wokwi v1.4.2. A two-instruction probe showed that one bit followed by conditional push at an eight-bit threshold produced one RX word instead of the documented zero. The eight-bit and control cases produced the documented levels. The retained replacement branches on Y before the final bit and executes unconditional PUSH only after the eighth IN. This recovers the numerical S+2 result without changing upstream code. Real-silicon manual conditional-push behavior was not tested. [Vendor PUSH operation, §3.4.6.2](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf#page=317) · [Pinned decoder](https://github.com/wokwi/rp2040js/blob/cab5fae8d72f44dc300dc139fb6e600f95e8031e/src/peripherals/pio.ts) · [Public FIFO probe](records/push-probe.json)

Input bypass requires a physically synchronous external path. As a conditional calculation, use GP2 clock-out and GP1 MISO, a 480 ns response after the CPHA1 launch, 5 pF load and the specified 1.8 V I/O settings. The vendor tables give up to 7.08 ns for clock flop-to-pad, 5.22 ns from GP1 pad to synchronizer, and 5.45 ns from GP1 pad to IN flops with bypass. Before cable, connector, target threshold uncertainty, clock uncertainty and receiving-flop setup, the 500 ns half-period then leaves 7.70 ns or 7.47 ns respectively. The emulator did not run an analog 1.8 V fixture. The project's edge-only value at one digital tick supplies no guaranteed setup time. A suitable real bench would hold the target and clock frequency fixed, sweep actual MISO transition phase across both sides of S, capture both endpoints, compare the synchronized and bypassed CRC/error counts and preserve temperature, load, voltage and instrumentation uncertainty. ## What the host did

Cold setup's 112 operations include 30 image writes, 30 forced jumps and 30 disabled public SM_INSTR readbacks. The remaining 22 configure clock, pin muxes/pads, shift directions, counter, data, idle directions and IRQ. One additional enable write launches the operation. After 400 late-observation clocks, one IRQ read and one destructive 32-bit FIFO pop retrieve the terminal result. Of the cold 112, eight access APB-mapped GPIO/pads and 104 access PIO on AHB-Lite. Per-edge FSTAT/IRQ probes are passive instrument observations. They do not feed the running program. A projected byte after the first FIFO-not-empty transition uses the final pop's value. It is not a contemporaneous nondestructive read of the intermediate FIFO data. The PIO self-jump with sticky IRQ cannot reproduce a VM terminal PC, HALT status or repeated nondestructive raw-register reads.

On one persistent SM/memory object, the eight-frame sequence ran modes 0→1→2→3 twice, LSB-first then MSB-first, alternating TX/RX 96/69 and 3C/A7. Each of seven rearms used 13 MMIO operations plus launch and the two terminal reads. The host consumed the prior word, checked prior FIFO-empty and terminal IRQ, released all output directions before changing clock polarity, set shift direction, selected the entry address, preloaded the next payload and cleared IRQ. No program location was rewritten or reread. One warm access configures the GPIO clock mux and the remaining 12 are PIO accesses. The peer starts each transaction idle and the stage model settles before launch. A continuously connected board peer, streamed transfers, CPU/DMA overhead and relative host wall time remain unmeasured. ## Reproduce

Run from a repository checkout on H: containing the main council archive. Python 3.11+, Node, and the local Linux workbench image are required on Windows. Linux can run the pinned x86-64 assembler directly. The original run used Node v24.18.0 and Docker image `protocol-emulator-asic-workbench:2026-07-29`, ID `sha256:9e300db4db672314f6dc5394d19e4b7d5d72917588fa2a963ace1a8118391909`. Pass a fresh output directory. The replay fetches the 154,580-byte Raspberry Pi v2.3.1-0 tools archive and the 114,826-byte Wokwi v1.4.2 package, checks their archived digests and extracts only the assembler and CommonJS runtime. Use `--tools <directory>` to reuse a previously verified extraction. [Official assembler archive](https://github.com/raspberrypi/pico-sdk-tools/releases/tag/v2.3.1-0) · [Pinned Wokwi source](https://github.com/wokwi/rp2040js/tree/cab5fae8d72f44dc300dc139fb6e600f95e8031e)

```powershell
$pioSpiReplayer = Get-ChildItem -LiteralPath evidence/E0049-review-council -Recurse -Filter conditional_push_probe.cjs | Select-Object -First 1
python -I -B (Join-Path $pioSpiReplayer.Directory.FullName replay.py) build/council-pio-spi-replay --history
```

The optional `--history` reconstructs three earlier source versions and checks all previous cases, including the 104 stalled attempts. The last stage always checks all 536 single launches, the same-SM sequence, exact image bytes, each recorded control, host transcript and the combined raw-row SHA-256. The final raw file stores three bytes per public edge in case order: GPIO outputs, enables and flags (RX-not-empty bit 0 and IRQ bit 1). Its decompressed SHA-256 is `f2e2bdd2ace70053c897803599df1f25d75660f42bdb53f3b574c71a2f46aaf3`. Stage manifests retain times, exact counterexamples and tool/source identities. They share a decoder and expected equations, so a clean rerun demonstrates repeatability within these assumptions.
