# Duration-neutral guard and stretch challenge

Freeze 2026-11-24 15:02 UTC following the first guard result and before the follow-up executes. This directly answers the architecture seat's question about preserving duration and late/held SCL behavior. Use the same retained G4 combined transaction, unmodified production sources, digital SRAM, 50 MHz, 5 ns ideal wired-AND resolver and target. Add the same WAIT after each SCL-low SET and subtract the same number of clocks from each 260-count low dwell. Branch targets use the assembler. No electrical crossing is fed back.

For unstretched traffic test 8, 24, 170 and 171 added clocks. Predict the first three retain all 38 SCL rise/fall pairs (the initial fall has no preceding release), START/repeated START/STOP and HALT timestamps of the archived transaction; the decoded bytes and ideal oracle should pass. With maximum observed baseline controller data change 40 ns after its falling clock, 170 clocks gives 3440 ns and 171 gives 3460 ns; the latter should fail the 3450 ns digital valid bound despite the expected data. A mismatch limits or rejects that bound. It is not a universal physical maximum.

Use the 24-clock variant for the following transactions at the same address, write byte and read byte. Run NACK at first address, data and repeated-start address. At each of the 38 release positions, inject SCL held until the last-but-one observable edge, the final observable edge, the first late edge and permanent low: delays 199987, 199991, 199992 and infinite five-nanosecond ticks as in the existing frozen contract. Require OK with expected data for the first two and TIMEOUT with compliant release and terminal deadline for the other two. Require the applicable full public oracle for every run. Compare the 24-clock no-stretch SCL/boundary/HALT events to the original G4 success. Measure and report any failed control. Preserve the list of cases and trace hashes and compact failing traces. One Icarus build, 159 transactions, 12 wall-clock minutes, under the total 8 MiB scratch cap. No cross-simulator, gate-level or board qualification is claimed.
