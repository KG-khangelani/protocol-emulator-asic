# How much of the occupied program store is repeated instruction data?

Measure the exact thirteen G3 program binaries in G4's original program-tools ZIP and the two original G5 firmware programs. Compare G3 with its independent copy in G5's continuity run and the two G5 copies with their archived Windows builds before scoring. The unit is one separately loadable program. Summing programs estimates a collection of files, while the physical chip executes one resident program at any moment.

Use one transparent hypothetical dictionary encoding. The four header bytes are the version, word count, distinct-word count, and fixed index width. The dictionary holds each distinct literal 32-bit word once, ordered by first appearance. The index stream uses the minimum fixed width `ceil(log2(distinct))` bits, little-endian packed into bytes with zero tail padding. One unique word needs zero index bits. No uncharged global vocabulary, shared state, cached decoder or literal escapes. Round-trip by reconstructing every original word in order; record each original and encoded digest, length and fraction, both the sum and the largest separately resident byte count. Compare to unadorned released binaries. A raw fallback, if considered, must pay its own discriminant.

Predict that repetition helps the longer controller programs, and that at least one shipping program and an all-distinct 128-word control will grow. Use one-, two- and three-token synthetic cases across byte packing boundaries, an all-equal legal 128-word program, and a 128-word legal program with distinct instructions. Include out-of-range index, short stream, extra data, invalid width and nonzero padding as decoder rejection tests. This is a static content study with a ten-minute design/implementation cap and no EDA run. Reject a blanket improvement unless all fifteen shrink, the controls round-trip and a 128-word arbitrary program stays within 512 bytes. Report the result even on rejection. Only same-process implementation, fixed-cycle fetch, full loader/readback compatibility and a smaller permitted complete configuration could establish a hardware benefit. The installed 256×32 macro and its area stay fixed in this study.
