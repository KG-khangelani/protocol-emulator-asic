# Externally clocked mode-0 SPI emulator test device

Frozen 15:40 UTC on 24 November 2026 before firmware, traces or simulator execution. Cut off at 16:18 UTC. Allow one VM firmware candidate and one engineering diagnostic if a failure needs characterization, with no production input edits. Allocate at most 3 MiB additional panel H: scratch. The purpose is a new **target** role on the qualified 0x22 engine. The test device has invented opcodes and no commercial-device compatibility claim.

**Interface.** Use CPOL=0, CPHA=0, MSB first. One externally driven active-low CS frames a command byte and one dummy/reply byte. The external SPI requester owns SCK (UIO0), MOSI (UIO1) and CS (UIO2) from before selection through completion. The VM owns only MISO (UIO3) when returning an accepted response, and uses UIO5:4 for terminal markers. MISO must remain released through all eight command sampling edges. With CS low, external SCK falling after command bit zero begins response bit 7. Requester samples all eight reply bits on its own subsequent rising edges, with at least 60 ns modeled setup and 40 ns modeled hold. A sampled 0xA4 command must return 0x3C, and 0xA5 must return 0xA7. Other command bytes must leave MISO released throughout and produce error marker 2. OK marker is 1 after the reply and deselection; a missing-clock timeout marker is 3. Terminal markers require HALT. An external pull-down on MISO in the model makes direction instrumentation necessary to distinguish release from driving zero. All uninvolved UIO remain released.

**Host.** The 50 MHz project clock continues throughout the measured interval, with the project powered. A separate fixture clock source, independent of the program PC and any VM pin changes, schedules every SPI transition. No loader/MCU transfer, status selector change or service is allowed from launch through terminal. Apply the staged cold loader, verify the original release assembler's entire occupied program and its payload bytes, record words and clocked setup steps, connect the idle requester only after MCU release, and exit E7 → 67 → 00 before execution. Command sizes and responses come from this contract independently of the assembler listing. Supply at least 300 ns from CS falling to the first SCK rising edge and 300 ns from final SCK falling to normal CS rising. Require release of MISO within 160 ns of its normal final falling edge.

**Cases and criteria.** Test all 256 opcode bytes at 1 MHz and 7 ns phase against the core-clock reference. A4/A5 must each send eight correct reply bits; all 254 others must reject. Test both positives also at half-periods 250, 500 and 1,000 ns (2, 1 and 0.5 MHz) and four external phase offsets 1/7/13/19 ns. Add an acyclic outside clock schedule with unequal high and low durations in that range to challenge an internally replayed schedule. Repeat the principal bad-opcode/missing/late/CS cases with explicit names. Count damaged transactions from the first observed violation, retaining the bad bit, timestamp or marker. A missing SCK after several command bits and a first SCK delayed 3 µs must produce timeout before any reply, within 2 µs of the relevant last activity. After timeout, later clocks cannot restart the transaction. A correctly selected intentional reply mutation must be caught at the affected received bit. Keep external SCK/MOSI/CS free of any chip drive. No new RTL or matched PIO target result follows.

**Separate stronger gate.** Deassert CS while MISO is actively transmitting, stop SCK, and observe whether MISO releases within 160 ns of CS rising. This tests the ability to share MISO with another selected target after an asynchronous abort. A target that passes normal exchanges but fails this requirement must be reported as such. Record the actual release latency, terminal marker and any limiting instruction/handshake. Count inspection separately from the 256-command screen. Hold the peer quiet throughout startup and test byte/direction readback rather than simulating a board.

Before simulation, select unchanged G4 production RTL with both qualified SRAM models for the full matrix. If budget remains, repeat a named positive for each opcode, a bad opcode, missing and late SCK, and the stronger CS abort on the original submitted functional netlist to check representation dependence in those cases.
