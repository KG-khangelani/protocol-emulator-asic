# A 59-word externally clocked SPI target and a failed abort bound

**A controlled frame works.** The unchanged G4 temporal machine received a digitally supplied mode-0 command and sent the matching response using a 59-word program. Two opcodes and responses define a small emulator test device. It demonstrates a target role in which the requester supplies every SPI clock edge. The 50 MHz project clock runs independently, while the control host makes no transfers or selector changes after launch. A byte-verified, staged cold load took 498 rising edges, with 236 written and 236 reread program bytes in eight banks and both payload registers separately checked. The program SHA-256 is `8d257ace7cc236c3ff5b2b71242679422f81900b6ee10dbd0daa78a7f318a81e`.

**A stopped clock exposes a separate limit.** With active MISO and CS deasserted 140 ns after the first response rising edge, the requester stopped SCK high. The target continued driving for 1,563 ns after CS rose; the frozen maximum was 160 ns. HALT with timeout marker followed after 1,584 ns. The original RTL and the submitted functional netlist returned the same failure. A second target allowed to drive after 160 ns could therefore overlap this source. This is sufficient to reject unconditional sharing of MISO under the stated abort contract. Electrical current is outside the model.

During command the target checks the first seven common MSB-first bits and uses the eighth to select a preloaded response. SHIFT_STEP supplies the reply bit on subsequent low phases. Public SCK determines each step. Firmware checks CS before and after the wait for high SCK, and then performs a bounded wait for low SCK. Once in that single-pin wait it cannot concurrently inspect CS. The bench observes resolved MISO and chip output enable; those internal-direction conclusions need independent instrumentation before promotion to an actual board. ## Three possible responses to the abort failure

1. **Shorten the single-pin wait.** A separately declared RTL diagnostic swept all 81 falling-edge wait operands from 0 through 80 while preserving every other instruction. It ran four 500 kHz phases and the active-MISO abort per operand, 405 simulations in total. The slow valid transaction needed 48–80 in all four phases. Only 2–9 released within 160 ns while MISO remained active at CS deassertion. Operand 9 gave 143 ns, 10 gave 163 ns, and the first slow-valid operand (48) gave 923 ns. Operands 0 and 1 had already dropped MISO before CS deassertion. None of these operand settings solved both requirements. This is a result for these two wait sites and these schedules.
2. **Poll CS and clock in bounded alternation.** The stock ISA has a single active loop. An absolute WAIT_PIN branch abandons that loop and any partial serial shift. A straightforward alternative explicitly emitted reply levels and used finite two-predicate loops per edge, with a local release on missed deadlines. Its actual source used 215 words (33 command, 88 and 90 for the two replies, four cleanup). The released assembler stopped at the 128-word limit. This establishes a cost for one construction, leaving an optimized control-flow encoding open. To advance it, repeat the original rates/phases, all 254 invalid opcodes, both valid replies, clock-loss deadlines, minimum setup/hold and normal/aborted 160 ns release. Add aborts across response bits and both clock phases plus valid and premature reselection.
3. **Gate the connection externally.** A default-open bilateral switch could disconnect remote MISO at raw CS deassertion while preserving its high impedance through the command. A unilateral buffer enabled simply by CS would drive a floating input during command. Another implementation could provide a validated response-enable signal and a tri-state buffer. Declare part, pin/channel cost, propagation, capacitance, supplies, level thresholds and default-off state; isolate normal loader reads/writes independently. A raw CS gate can reopen upon a second selection while the VM still holds stale MISO. Add an enforceable frame-permission/rearm policy and test a second complete frame, a premature reselect, equal-level and opposing-drive probes. A real fixture or separate digital switch experiment supplies evidence for that arrangement. The current physical candidate has no such device.

This is a purpose-built emulator interface with two opcodes, one continuous selection and one completed frame per arm. It does not implement a named peripheral, imply sustained multi-frame data service or compare an SPI-target PIO implementation. The missing/late cases, model-clock phases and times have specific bounds. The 160 ns limit is the council's engineering target for testing bus handover. The original failed source, representative wire logs, code-identity receipts and every diagnostic result are retained.
