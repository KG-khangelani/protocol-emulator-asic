# Delivery rebuttal and decision boundaries

**Updated after the complete selected-power runs.** Tying enable high and staging the launch produced matching 55 G3 records on the G4 netlist and Verilator RTL, all 20 physically applicable G5 traces on Verilator RTL and G4 Icarus, and all 1,160 retained I2C records on the G4 netlist. This supersedes the initial uncertainty about ordinary runtime coverage on the changed startup. The electrical and human questions need different observations.

| Work item | What it can discriminate | Stop or reverse |
|---|---|---|
| First-time reader and owner | Can the participant identify the physical candidate and software release, predict a timing change, obtain the expected output without a hint, and explain an actual limitation? Log human elapsed time, assistance and the point of failure. Use the project's own rubric separately for G6. | If readers already locate the correct artifacts and meet the task, end broad prose work. Repeated confusion about one item justifies a targeted correction and a fresh reader. |
| Runnable cold host profile | Does one controller sequence use available signals, preserve startup, fail at a bad byte, leave the peer outside loader reads, and produce the expected public trace? Running the profile against existing cases should reuse the current gates. | A physical claim stops at the first inaccessible control, unknown peer owner or unbounded setup/turnaround. A clean implementation and negative controls complete the logical task for the stated profile. |
| New SPI-target workload | Can unchanged firmware classify an externally clocked command and return its reply with an idle loader? Can it release MISO promptly on aborted CS? The 59-word target gives affirmative normal transaction evidence and a negative 160 ns abort witness. | Preserve the applicable single-frame contract. A true matched PIO target with the same CS abort, reselect behavior, timing and loading costs could promote comparative work. The existing PIO SPI master and the existing PIO 1-Wire initiator have different jobs. |
| Calibrated fixture | What voltage and time does the actual receiver see at its threshold under a stated load? Which drivers are physically connected at each handoff, how fast does clock/start occur, and is MISO released before another source may drive? | With an appropriate fixture and named peer already in hand, take the smallest instrumented test capable of changing the board claim. If isolation, probe bandwidth, known input thresholds or fresh-frame arming cannot be established, record that limit and postpone connection to a live shared bus. |

Panel A's strongest case is the compact, matched 1-Wire implementation that removed any inference of uniquely efficient expressibility from a single new workload. Its new SPI master evidence verifies a distinct externally observed task. Panel B's strongest case is a threshold calculation and a same-level contention example that survives any number of zero-delay repetitions. The 1,563 ns active-MISO abort is already a precise digital rejection of the 160 ns contract. The remaining physical work would measure a named fixture's achievable envelope; it cannot negate that observation on the unbuffered model.

My weakest premise is that a new reader will struggle. Existing programs reproduce from two small downloads, and a person may navigate them promptly. A counterbalanced reader trial can disprove the need for more guidance. With no accessible fixture, delivery work should start with the cold profile and this short trial; research can compare the same target role or improve its bounded polling. With a suitable fixture in hand, a specific live-peer claim can bring a single calibrated test ahead of another architecture pilot. Preserve the physical candidate and run the pending organizer check regardless of the ranking. These are project decisions and do not forecast judging outcomes.
