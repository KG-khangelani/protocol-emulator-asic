# Reusing a verified resident I2C program

**Recommendation.** Preserve a full independently checked cold load as the recovery route. Study an opt-in resident call for one controller that retains exclusive custody of a still-powered image and consumes only qualified terminal results. The original demand for identical complete cold/warm observations failed. A separately registered valid-gated diagnostic passed on release RTL and the archived full G4 netlist under Icarus. The current 96-word combined write/repeated-START/read firmware makes the trade especially visible. [Published I2C result contract, including stale data](https://github.com/KG-khangelani/protocol-emulator-asic/blob/5bdc0e6b6449a829a5da1f8f9a8060257e974843/docs/specs/p-i2c-controller-100k.md#public-result-and-bounded-waiting-policy)

The fixture kept the project powered throughout. It used separate MCU and open-drain peer drivers and an explicit peer isolator. It parked the clock for direction changes, disconnected the peer during reads and writes, verified sampled program bytes, connected the idle target while at E7, clocked E7 twice, then selected 67 and 00 before starting. The testbench could inspect chip output enables. A physical controller has to establish chip release from the qualified sequence and fixture measurements. Its own direction register and sensed pin level alone cannot establish exclusive ownership.

## Cold and warm work on the same second transaction

The first transaction addressed 0x52, wrote 0x96 and received 0x69. The second addressed 0x2a, wrote 0xd2 and received 0x3b. Each cold run sampled reset and wrote/read back all 384 program bytes before commit. The warm run evaluated the previous terminal fields, parked in loader mode, read length 96, wrote and read back both new payload bytes, re-established idle and started at PC zero. All accepted wire results include both addresses, the data byte, target ACKs, repeated START, received byte, NACK, STOP, bus-free interval and HALT. The existing independent target observed bytes `54 d2 55` in hex on the changed transaction. Its terminal delay measured 80,584 five-nanosecond ticks from the judged initial idle point in both runs.

The eight warm edges perform park, read length, write and read TX0, write and read TX1, and two idle flushes. The full cold B fixture also performs 390 post-edge data/status comparisons, the warm fixture five. Instrumented per-edge output enable checks are separate from those counts. Firmware execution spent 402.92 µs from judged idle to HALT. Real end-to-end time includes the clock source, GPIO write and sample overhead, external isolation and transport settling. A manually disconnected peer can consume most of the time despite the 794 saved clocked host steps.

## The failure defines the software contract

The strict attempt ended during RTL comparison at 15:16 UTC. Its warm/cold B traces differed on 78 of 373 event rows. At the first row, both reported `rx_valid=0`, while raw RX was 0x69 for the warm operation and zero after the fresh reset. The published data store clears validity on a TX payload write and leaves the preceding raw value in place until the next shift write. In the separately registered run, masking **only** RX while its valid flag was zero made each row, field and timestamp identical for changed B and repeat B versus fresh cold B. The projected SHA-256 was `4366add49dee57e2387f288f2a4076a7f0f9c7d24ec4a755fe0f6c96fafaab49`. An application accepting I2C data additionally requires the terminal OK state, expected bus cleanup and correct wire exchange; the valid flag alone can also describe intermediate shift data. [Data store implementation](https://github.com/KG-khangelani/protocol-emulator-asic/blob/5bdc0e6b6449a829a5da1f8f9a8060257e974843/src/m1_data_store.v#L15) · [I2C result rules](https://github.com/KG-khangelani/protocol-emulator-asic/blob/5bdc0e6b6449a829a5da1f8f9a8060257e974843/docs/specs/p-i2c-controller-100k.md#public-result-and-bounded-waiting-policy)

Actual bank selection with an intentionally stale software custody flag cleared ready/status and length to zero. The host observed the terminal mismatch before any warm payload write or execution edge. A second control changed just instruction 1 from a 235-clock WAIT parameter to 238. It legally returned 0x3b and took 12 extra target ticks (60 ns, three project clocks). At the end both distinct 96-word binaries presented identical guard fields: status 0xb3, full PC 83, interface 0x22, raw-valid 1, RX 0x3b, bus/marker low-five value 7 and length 96. Their hashes and their earlier wire histories distinguish them. An unknown-custody host refused to touch a pin. Reading the whole image again could check identity, with the bank-selection/recommit cost that the optimization seeks to avoid.

**Panel B's objection and our response.** The practical precondition is a host-owned session epoch anchored to successful full byte verification. Destroy it on detach, program reselection, reset, power change, possible second writer, host restart, interrupted setup or any interval of unknown ownership. A held bus can survive the VM's terminal timeout. For this candidate, previous HALT/OK and independently established external idle/ownership are required; a TIMEOUT or execution fault takes a different recovery path. Register the external isolation and measured turnaround/start bounds. No physical throughput claim follows before these conditions can be implemented and timed.

**What would change the ranking.** A repeat workload with measured transfer overhead and a known automated isolation path could justify a second host profile after the cold sequence qualifies. One stale epoch accepted after reset/overwrite, ignored invalid raw value reaching an application, lost external idle, or unbounded isolated-target delay is sufficient to withhold it. Estimate 0.5–1 engineer-day for two-simulator qualification of the gated API, epoch recovery and adverse starts on fixture models, after the cold transport exists. Add measured hardware time separately. The council measured one normal partner/one response schedule, one bank-invalidated state and one distinct binary. It did not exercise arbitrary in-flight interruption, reset timing, other protocols, actual ETR GPIO or a fabricated device.
