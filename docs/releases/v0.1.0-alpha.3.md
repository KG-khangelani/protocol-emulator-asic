This research prerelease records the bounded SPI phase1 capacity study.
Mode1 saves one instruction and reaches nine words; mode3 remains at ten in
the examined family. The hardware store remains eight words.

### Changes and checks

- Correct the oracle to accept one complete initial low-clock idle interval
  before mode1 CS assertion; preserve all waveform and setup/hold checks.
- Screen60,000 timing layouts and6,920 declared reference schedules. No
  seven/eight-word candidate passes this family; this is not an ISA lower bound.
- Check3,072 positive paired-byte reference transactions and four edge-only
  input counterexamples. Nine/ten-word positives are model-only.
- Both Icarus and Verilator reject all108 shortened eight-word images and four
  oversized loader commits, with identical public case records and traces.
- Require this screen in focused CI and release publishing, alongside the
  existing sensitivity, four-mode and held-program proof gates.

[E0029](https://github.com/KG-khangelani/protocol-emulator-asic/tree/v0.1.0-alpha.3/evidence/E0029-phase1-capacity-screen)
retains the declared search, input hashes, model witnesses and simulator traces.
Production and compact RTL are unchanged. There is no fitting phase1 RTL
success, global minimum proof, new physical qualification, Fmax or silicon claim.
The proposed timed GPIO experiment is future work, not part of this hardware.
