# G3: readable programs for the qualified shared protocol core

This milestone adds a small versioned assembler, timing listings and public
load/readback/run plans for G2's unchanged SRAM core (interface 0x22).
It adds thirteen readable examples: UART transmit and bounded receive, both
bit orders of all four SPI modes, and I2C write/read/repeated-START transactions.
Their machine words exactly match the independently encoded G2 programs.

Clean committed-source CI and a separate clean local clone pass twenty assembler
acceptance tests and four public-interface groups / 55 cases per simulator.
All normalized observations agree between Icarus and Verilator, including 15
expected rejections. Windows, Linux CI and the clean clone produce the same 53
program files byte for byte. The local full repository check passes 147 tests.
E0046 retains original archives, logs, source bindings and a portable audit.

The G3 download includes the standalone Python assembler, readable sources,
compiled binaries, JSON images, timing listings and loading plans. The two
original CI archives and G3 manifest/checksum list are separate assets. The
release source preserves all 351 verified toolchain inputs from implementation
commit 0297655; the milestone publication adds its own checked workbench image.

Build and verify from a checkout:

```powershell
.\tools\workbench.ps1 Programs
.\tools\workbench.ps1 ProgramTest
```

Linux uses `./tools/workbench.sh Programs` and `ProgramTest`. Outputs go to a new
directory under `build/programs/`. See `docs/programming.md` for writing a source,
reading its schedule and following the public pin-level plan. Invalid programs,
bad target versions, capacity errors and readback mismatches fail before run.

The twenty qualified physical inputs are unchanged. Alpha.6 retains G2's actual
routed/timing/precheck/netlist evidence and original downloads; this software
milestone does not rerun or replace physical qualification. Its production
profile still identifies that original alpha.6 hardware adoption.

UART receive remains bounded with explicit framing, delivery and host-service
limits. SPI requires the declared input-hold profile. I2C validation is digital,
with stated open-drain, pull-up, stretch and cleanup assumptions. No new analog,
silicon, maximum-frequency, minimum-ISA, owner-fluency or final-submission result
is claimed. G4 submission readiness remains separately queued.
