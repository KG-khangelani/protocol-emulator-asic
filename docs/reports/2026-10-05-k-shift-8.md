# K-SHIFT-8 progress and decision report

Date: 2026-10-05. Scope: simulation-first M1-T09 engineering.

## Outcome

K-SHIFT-8 is implemented as a three-word public-pin-loaded kernel. One
protocol-independent SHIFT_STEP executes inside the existing bounded LOOP eight
times, followed by HALT. The same program sends and receives one byte in either
bit order in exactly ten accepted execution edges. TX payload, RX result and
RX-valid are accessible through loader-mode registers; no payload is compiled
into the program image.

The acceptance contract was frozen first in `specs/k-shift-8.md`. It defines
encoding, pin direction, synchronized input schedule, reset/enable priority,
partial-byte failure, data-register lifetime, exact edge tables, adversarial
cases and the evidence boundary. D15 records why a composable one-bit primitive
was selected over a monolithic protocol or byte-transfer instruction.

## Verification and measurement

The complete locked 11-stage evidence collector passes locally: doctor, static
consistency, learning-status safeguards, lint, eleven cocotb cases under both
Icarus and Verilator, the separate GL-shaped smoke, waveform provenance, the
readable learning waveform, formal verification and generic synthesis. The 16
independent Python-model checks also pass. The public K-SHIFT-8 case checks both
bit orders, every TX bit/direction, synchronized RX assembly, same-edge
eighth-bit result capture, reserved/read-only writes, and RX-valid invalidation.
The direct-engine trace is compared edge-for-edge with the semantic model in
both bit orders and through an interleaved SHIFT_STEP/SET/WAIT loop. The public
test reads RX/result-valid immediately after the eighth shift and before another
rising edge, so a deferred engine-to-store handoff fails. Adversarial cases
check disable freeze, equal TX/RX pins, reserved bits, mid-byte configuration
changes, HALT after seven bits and reset from an active partial transfer.

Formal properties cover shift start, progression, configuration stability,
same-edge completion, result data, partial HALT, reset/freeze, and independent
data-store reset/write/capture/readback behavior. Existing program-store,
input-synchronizer, WAIT/LOOP, terminal-state and expected-failing mutation
checks remain active.

Generic Yosys screening reports 2,534 abstract cells and 385 state bits. The
K-BOUNDED-LOOP baseline was 2,175 cells and 341 bits, so the delta is +359 cells
and +44 state bits. The state delta is fully accounted for: TX/RX/valid data
registers use 17 bits and in-progress shift state uses 27 bits.

An earlier registered result handoff screened at 2,512 cells and 394 state bits.
It was rejected despite 22 fewer abstract cells because it added nine state bits
and a hidden commit edge. That transient working-tree screen has no retained
standalone artifact; it is recorded as an ablation, not as durable evidence.

## Constraint and governance check

The [official Jane Street page](https://blog.janestreet.com/protocol-emulator-asic-competition/)
was rechecked on 2026-10-05. It still specifies
an open-source general-purpose reprogrammable protocol emulator, a 6x4 CMOS5L
target, UART/SPI/I2C as starting protocols, and a 2027-01-18 deadline. K-SHIFT-8
is only a reusable serial datapath microkernel; it does not satisfy any complete
protocol workload.

Engineering proceeded autonomously under D8. M0 owner fluency remains
`PENDING`; no learning record was promoted. No physical flow, gate netlist,
timing/Fmax, hardware purchase, competition submission, credential, OS change,
or external message is part of this work.

## Failed or blocked attempts

a first independent review found no apparent RTL functional defect but blocked
release on two verification gaps. The integrated public test observed RX only
after HALT, and SET/WAIT preservation plus byte extremes were model-only. The
review fixes move the integrated read before another rising edge, exercise both
byte extremes and an interleaved loop against RTL on both simulators, and add a
formal invariant that every non-shift transition preserves all shift state.

The first complete collector over those fixes, retained under
`build/evidence/20261005T052333369474Z`, failed both simulators because the new
test incorrectly expected the completion strobe during interleaved SET/WAIT
instructions after seven bits. The RTL correctly kept it low until the eighth
SHIFT_STEP. The expectation was narrowed to that instruction; focused dual-
simulator tests and the subsequent complete collector pass. The failed bundle
is not relabelled as successful.

The first lint run rejected two short one-hot literals. They were expanded to
explicit eight-bit values; lint and the complete collector then passed. The
first host wrapper attempt was blocked by workspace permissions around the
personal Docker runtime configuration/API. No denied path was accessed or
modified; the locked workbench passed after using an isolated workspace-local
Docker configuration with approved daemon access. Neither event is recorded as
a design pass.
