# Compact phase formal qualification contract

Status: proposed experiment, 2026-11-03. Inputs are PR11 candidate head
`f0c41fcf3aaca14a76dd0c45a23f259599de24fd` and the frozen
[phase encoding contract](spi-phase-comparison.md). Production RTL is immutable.

## Model and assumptions

The DUT is the compact executor generated by `build_variants.py`, not an SPI
peripheral or the full chip. Formal-only output wires expose its two phase
flags without changing inputs, registers or transition logic; retain the exact
instrumentation diff/hash alongside the uninstrumented candidate hash.

All 32 instruction bits, instruction-valid, synchronized input bits, both TX
payloads, enable and reset are symbolic on every clock. The first sampled edge
must reset the engine. After that, reset and enable are unrestricted, including
repeat reset and indefinite disable. No fixed pins/order/payload, valid-program
stream, eventual enable or external SPI timing is assumed in the safety job.
`sampled_inputs` is already synchronized digital data. This proof does not model
the synchronizer, asynchronous input timing, loader/store or metastability.
The unchanged top's effective reset is `rst_n && program_ready && !load_mode`;
core reset properties apply conditionally to that wiring, without claiming a
new integrated loader proof.

## Safety obligations

- Sampled reset wins over enable, clears phase/shift state, PC/wait and GPIO.
  Disable and terminal states hold all executor registers; no result pulse.
- Prepared implies an active phase byte and active shared shifter. Pending
  phase SAMPLE has period marker1, a positive remaining count and prepared
  operands. Legacy timed bursts use period>=2 and cannot be a phase byte.
- DRIVE validates opcode/reserved bits, distinct pins, non-overlapping aux
  mask, phase ordering and byte configuration. It updates only the specified
  GPIO fields and TX shift, initializes RX/count only at byte start, prepares
  exactly one sample and advances the PC under existing LOOP semantics.
- SAMPLE before DRIVE, duplicate DRIVE, incompatible pins/order, legacy/phase
  interleaving, partial HALT and invalid HALT/SHIFT/phase-family encodings fault
  without GPIO/RX commit or shifter mutation. Invalid ordinary opcode families
  retain their prior implementation; their legacy-only behavior is compared in
  the refinement job below.
- Valid delay0 captures on execution. DelayN>0 holds PC/GPIO/TX/RX while its
  positive 16-bit counter decrements once per enabled edge; count1 captures
  exactly once using latched pins/order and that edge's synchronized input.
  Changed instruction/valid/payload inputs during pending wait cannot refetch
  operands or change the countdown. Disabled edges do not consume delay.
- Capture alone advances phase receive count/assembly. Samples1..7 do not
  commit; sample8 commits the correctly assembled byte on the same edge and
  clears phase state. Invalid accepted RUN fetches and faulted/disabled/reset
  edges cannot manufacture a result write. Existing legacy completions remain
  allowed; phase operations preserve the legacy payload-slot flag.

These are assertions, not assumptions restricting the DUT to behaving properly.
The delay field retains all 16 bits. A successful induction proof of the
decrement/capture recurrence covers that local rule for every count; it is not
a 65,535-edge completion trace or wall-clock liveness under arbitrary stalls.

## Legacy refinement and anti-vacuity

A paired executor job compares all architectural state/status, GPIO and result
outputs with the unchanged production executor under shared symbolic inputs.
At an enabled valid RUN fetch only, exclude the two newly allocated manual
phase word types (opcode10, bit29=1, bit21=0, mode01/10). Every previous legal
instruction remains admitted; excluded words were previously invalid. Inputs
ignored during wait/disable remain unrestricted. This job does not assert
equivalence for the new extension or for every formerly invalid word.

Bounded covers must reach immediate and delayed capture, eighth-sample commit,
pending disable/resume, reset during pending wait, invalid sequencing, a legacy
byte completion after a completed phase byte, and entry
to delay65535 followed by decrement65534. The maximum delay need not complete
within the cover horizon. Mutation jobs must reject a decrement-by-two phase
counter and a phase result commit at sample7. Keep their counterexamples.

Record each task's mode, depth, engine, assumptions, actual status and witness
step. Distinguish k-induction PASS (written invariants for arbitrary length),
BMC PASS (only its finite horizon), reachable cover and expected mutation FAIL.
Timeout, unknown, missing witness or tool error is not a pass. Proof depth and
cover depth will be fixed in the runnable task files before execution and
reported exactly. Final proof jobs use configured depths 8 (phase) and 12
(refinement), covers 40, and mutation BMC depths 8/20. Cover checks require all ten
phase and three legacy obligations plus retained witnesses. A green result is
partial executor qualification, not full
SPI mode coverage, complete-chip/physical timing or production readiness.
