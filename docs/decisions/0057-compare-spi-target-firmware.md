Test the original 59-word SPI target, one revised program for the same 128-word VM and one full-byte program for a single RP2040 PIO state machine. Use the original 50 MHz model and one independently scheduled mode-0 requester. Freeze the [original roles and timing](../../evidence/E0049-review-council/panel-c/spi-target/spi-target-contract.md) and the [reselection contract](../research/council-2026-11-24/next-experiments.md#4-compare-architectures-on-an-externally-clocked-target) before running the candidates. Spend at most the council's one engineer-day. Keep scratch on H: and leave the physical inputs and original records intact.

- Send all 256 command bytes. Require A4 → 3C and A5 → A7 with at least 60 ns setup, 40 ns hold, released MISO through the command and normal release within 160 ns of the final falling edge. Invalid commands must leave the line released and terminate with error. Sweep both replies at 0.5, 1 and 2 MHz and four phases, plus unequal periods.
- Interrupt each of the eight response bits of both commands in both clock polarities. Score the driven value before abort, release by CS rise +160 ns, the complete opposite command after a 160 ns CS-high interval, and its quiet command phase. Return high SCK low at +80 ns in the reselect cases. Also hold the interrupted clock indefinitely for a bounded observation, including the historic 1,563 ns control. Check ordinary completion, invalid command, missing command clock, delayed first clock, early deselection and a missing clock while a response is driven.
- Use the release assembler and public cold readback for the VM. Try direct literal reply bits with frequent CS/SCK tests and a fresh command entry after an abort. Assemble the PIO with the official tool, read back the image through the emulated register interface and use real PIO instructions to decode the prefix and select one of two eight-bit replies. Count the status interface, cold preload, memory, pins, state machines, FIFOs, and any service during a frame. Keep a timeout, status, timing or rearm failure visible in the verdict.
- Retain the independent input schedule, public direction and resolved level changes, first failures, checker corruption controls and commands. Accept the full role only on all required outcomes. This digital comparison can establish a firmware result on the named requester. Hardware promotion requires a real application deadline and endpoint measurements.
