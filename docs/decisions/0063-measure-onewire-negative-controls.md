# D63 — Exercise the 1-Wire bench controls at the physical FPGA clock

25 November 2026. The remote FPGA has an accessible open-drain line, two RP2350 inputs on that line and a separate copy of its drive command. No connected DS18B20 has been identified. Use the board to qualify the no-device and stuck-bus controls needed for the sensor trial. Budget two cold-load repeats of three conditions on board 4. Leave the supply-response claim open until the FPGA exchanges `CC B4` with each real device. [Council sensor experiment](../../evidence/E0049-review-council/onewire/rise/README.md) · [Analog Devices DS18B20 specification](https://www.analog.com/media/en/technical-documentation/data-sheets/ds18b20.pdf)

Retain the 85-word council program's 500 µs reset, 76 µs write slots, 2 µs write-one and 62 µs write-zero low times at the FPGA's routed 12.5 MHz. Expose distinct terminal markers on the two unused VM output bits visible through the existing wrapper. Before programming the FPGA, read back the new image on the production RTL, decode the 16 command bits and seventeenth read slot and check both modeled power responses. Include incorrect-command and shortened-reset controls.

On the board use the routed FPGA bitstream from E0059. First, leave the bus pulled up with no responding device. The FPGA should generate just one reset, detect missing presence and halt with the error marker. Second, hold the bus low before launch. The FPGA should issue no reset or command. Third, start with the bus high and use a separate RP2350 pin to continue sinking it after the FPGA begins reset. The FPGA should release after 500 µs, observe the line still low and return the error marker. Capture the FPGA command, both observed DQ inputs and HALT. Verify the entire program at each cold load, check that terminal drive released and compare both repetitions. Acquisition on these controls cannot measure the power response of a sensor.
