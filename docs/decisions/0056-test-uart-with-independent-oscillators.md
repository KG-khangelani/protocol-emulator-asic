# D56 — Clock the FPGA receiver and external UART transmitter from separate oscillators

25 November 2026, South Africa. The preceding test programmed different baud rates on three state machines sharing one oscillator. The Welland public lab has two idle FabricFox v2 boards, each with an iCE40UP5K and an RP2350. The FPGA contains a free-running HFOSC hard macro. Use that oscillator directly for the receiver and the RP2350 system clock for the transmitting PIO. The populated breakout BOM gives no basis to assume an additional crystal on FPGA pin 35. ## Criteria fixed before building or running the fixture

- Make a bench-only FPGA wrapper around the existing five RTL sources and E0051 memory adapter. Clock all receiver registers and RAM directly from the one HFOSC output. Synchronize the controller's former clock input as a loader strobe or sustained run enable. Connect the oscillator to runtime UIO2 for observation. Retain all eight loader data pins. Check clock roots in the synthesized design, close timing, and pack and reproduce the image twice. Try the nominal 12 MHz divider at a 13.2 MHz timing screen. If timing fails, retain the failure and try nominal 6 MHz at 6.6 MHz. No qualified chip input or released image changes.
- While run enable is held low, capture the free-running receiver clock at GPIO27 against the RP2350 timebase. Record the complete digital samples. Estimate receiver clocks per second from the first and last rising edges. Use a 125 MHz nominal controller clock and 434 receiver clocks per UART bit. Test a fixed transmitter preset derived from the divider's nameplate **before using any clock measurement to set the transmitter**. Report a preset failure as observed even if adjusted tests pass.
- Choose one transmitter setting per board from the idle calibration and freeze it during all adjusted cases. Send two consecutive `55 AA` frames and a different `96 69` pair. Also test a transmitter programmed 2% fast and 2% slow relative to the calibration, then a bad first and a bad second stop at the matched setting. Each case starts with a cold program readback. The transmitter counts only RP2350 ticks and receives no frequency feedback during a frame.
- Sample UIO1 data and the adjacent UIO2 receiver clock together during the entire pair. Check the clock throughout the transaction, recover every wire transition and stop level, count receiver edges from start to start, and compare to the capture-derived transmit period. Require the matched rate within 0.5% of the intended ratio and the fast/slow rates within 0.5 percentage points of their programmed offsets. For valid adjusted cases require both intended bytes and `A7`. Fault cases require `E6` and no delivered bytes. Require the observed poll-gap plus read-sequence bound (including 2 µs quantization) to fit the two-frame service model at the measured rate. Keep the corrupt-readback control from D54. The success of an untrimmed preset is a separate result.
- Repeat on two named idle boards if available. Restore the original gallery selection and controller settings. Retain raw captures, failed attempts and an offline audit. Allow 75 minutes from 22:24 UTC, with all scratch on H:. These finite digital measurements cannot determine analog release latency, oscillator accuracy against a calibrated standard, or performance across supply and temperature.
