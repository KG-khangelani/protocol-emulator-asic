# D59 — Measure SPI recovery on a remote FPGA

25 November 2026. Exercise the [126-word E0056 program](../../evidence/E0056-spi-target-watchdog/README.md) on either available Welland FabricFox. Use the existing project RTL, the previously compared FPGA RAM adapter and the public loader. Read back the full 504-byte image. Use an external RP2350 requester and sample the actual MISO pad, the FPGA pad-enable signal routed to a second pin, the actual project clock and the terminal indication together. Release MCU drivers on all linked selector pins before SPI launch. Use the provider's documented public gallery and terminal and yield to an occupied board.

Try strict routing at 50 MHz and 12.5 MHz. Use only a clock the new fixture meets. At 12.5 MHz, replay the 384 abort/reselect and 32 selected-stall schedules at four times their original durations. Require active drive before each abort, commanded release within eight core clocks (640 ns), uninterrupted release during the fresh command, the correct opposite byte, and held-low CS reaching a stable released timeout by 100 clocks (8 µs). Check the actual input waveform, 240 ns setup and 160 ns hold at fresh reply samples. Report elapsed times at the board clock and the original 160 ns and 2 µs thresholds separately. Include ordinary exchanges, invalid input, a wrong program readback and a deliberately short handoff. Preserve first failures. A grounded digital reading cannot distinguish driven low from high impedance. Claim physical driver turnoff only with an identified and calibrated target-branch probe.

If the live fixture cannot run, route and test its package-pin interface offline and report what blocks the physical run. This advances the council's externally clocked target and receiver-end experiments. The board 4 pilot returned both fresh bytes at the deliberately short handoff while its enable witness stayed active into the new commands. Before any gap sweep, extend the council's named-requester comparison to locate a usable digital handoff on this fixture. At a nominal 1 µs SCK half-period, test CS-high intervals of 160, 240, 320, 400, 480, 560 and 640 ns over both commands, all eight abort bits, both clock levels and four launch phases (128 cases per interval). On a high abort, return SCK low halfway through CS-high. Report complete fresh service, observed drive at reselection and the smallest release-to-reselection margin. Select the shortest tested interval for which every case and every larger tested interval meet the original functional checks with positive margin after allowing one 8 ns sample interval. A finite margin on the digital witness leaves the analog branch decision open.

The first 421-case board 4 capture met all 32 timeout gates and delivered all 384 fresh bytes. Ten low-clock aborts missed the pre-abort data check. The expected bit appeared on the CS sample or 8–16 ns later. Preserve that matrix. Repeat all 384 reselections with abort 32 ns later relative to the previous SCK edge, holding the following 640 ns CS-high interval fixed. In the gap sweep compare both abort offsets on the same grid. Accept the later-offset observation only for the runs whose actual capture meets the original data, ownership, timing and terminal checks. Keep the two requester timings identifiable.

Also apply the original external wall-clock schedules directly to the safely routed 12.5 MHz core. Use the RP2350's nominal 8 ns grid, all 384 reselections, all 32 pauses and ordinary command controls. Keep the 160 ns release, 2 µs timeout, 60 ns setup and 40 ns hold criteria in these runs. Extend only the final observation tail to capture late terminals. Count an unrecognized command, missing drive or successful late reply against its corresponding strict gate. These runs characterize the actual FPGA at the original requester rate.

With the later abort, 400 ns left the witness active at reselection in nine of 128 trials. At 480 ns all 128 passed with at least 56 ns digital clearance. Refine that interval on the board sampler's 8 ns grid from 400 through 480 ns inclusive. Repeat the 128-case fastest-rate grid in descending gap order and require a strictly positive lower bound in every case at the candidate and at every larger tested interval. Retain the 480 ns result as a separately repeated operating point. These tests locate a boundary for this FPGA fixture and requester only.

In the reselection cases SCK returns low halfway through a high-clock abort. Isolate the council's standalone abort by leaving SCK at its last level and CS high through the end of the capture. Run the 32 E0055 held aborts at the original requester timing and at fourfold durations. Repeat the latter with CS rising 32 ns later. Require an active, correct bit before abort, release within 160 or 640 ns respectively, and a quiet enable for the rest of the observed interval. Check every SCK edge and both polarities. A later idle-selection timeout is separate from the selected-clock timeout gate.
